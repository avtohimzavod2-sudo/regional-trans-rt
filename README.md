# Regional Trans RT

Приватная цифровая диспетчерская платформа междугородних пассажирских поездок в Кыргызстане.
Пассажиры обращаются через **WhatsApp**, водители — через **Telegram**. Отдельного мобильного
приложения на первом этапе нет.

Пилотное направление: **Бишкек — Балыкчы — Чолпон-Ата — Бостери — Каракол**.

## Правовой статус

Regional Trans — информационный посредник, не перевозчик. Договор перевозки заключается
между пассажиром и водителем напрямую. Личные контакты обеих сторон передаются только после
взаимного подтверждения конкретной поездки.

## Как это устроено

- **Пассажир** пишет боту WhatsApp (`откуда`, `куда`, дата, время, места, багаж, точка посадки).
- **Водитель** пишет боту Telegram (маршрут, дата, время, свободные места, авто).
- Агент читает сообщения **только в подключённых администратором Telegram-группах**
  (`TelegramGroup.isActive`), распознаёт объявления пассажиров/водителей и приглашает их
  в приватный диалог — не отвечает публично и не показывает контакты в группе.
- Движок сопоставления (`src/lib/matching`) ищет подходящую пару по направлению, дате, времени,
  местам и статусу верификации водителя; сначала предлагает заявку водителю, затем — при
  согласии — предлагает поездку пассажиру. Контакты раскрываются только после согласия обеих
  сторон (`src/lib/matching/orchestrate.ts:revealContacts`).
- После завершения поездки водитель автоматически ставится в очередь на обратный рейс
  (`src/lib/matching/queue.ts`).
- Вся история (заявки, предложения, подтверждения, отмены, сообщения, действия агента и
  диспетчера) хранится в Postgres и видна в журнале действий диспетчерской панели.

## Структура проекта

```
prisma/schema.prisma        модель данных (заявки, предложения, матчи, поездки, очередь, аудит)
prisma/seed.ts               пилотный коридор Бишкек–Каракол + тестовый диспетчер
src/lib/matching/            движок сопоставления, очередь обратных рейсов, оркестрация
src/lib/nlp/extract.ts       извлечение структурированной заявки из текста (ru/ky/en)
src/lib/messaging/           адаптеры Telegram (grammy) и WhatsApp Cloud API
src/lib/ingest.ts            приём сообщений -> NLP -> запись в БД -> запуск матчинга
src/app/api/webhooks/        вебхуки Telegram и WhatsApp
src/app/dispatcher/          диспетчерская панель (ручное вмешательство, журнал аудита)
```

## Запуск локально

1. Скопируйте `.env.example` в `.env.local` и заполните значения (см. ниже, откуда их взять).
2. Установите зависимости и накатите схему БД:

   ```bash
   npm install
   npm run db:push
   npm run db:seed
   npm run dev
   ```

3. Откройте `http://localhost:3000/dispatcher` и войдите под пользователем, созданным
   `db:seed` (по умолчанию `admin` / `changeme123` — обязательно смените пароль перед пилотом).

## Откуда взять ключи

| Переменная | Где получить |
|---|---|
| `DATABASE_URL` | Postgres-инстанс, например Neon через Vercel Marketplace (`vercel integration add neon`), либо любой другой Postgres. |
| `AUTH_SECRET` | Сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`. |
| `TELEGRAM_BOT_TOKEN` | Создать бота через [@BotFather](https://t.me/BotFather), затем установить webhook на `https://<домен>/api/webhooks/telegram`. |
| `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID` | [Meta for Developers](https://developers.facebook.com/) → WhatsApp → API Setup. Требуется верифицированный WhatsApp Business аккаунт. |
| `WHATSAPP_VERIFY_TOKEN` | Придумайте любую строку и укажите её же при настройке webhook в Meta. |
| `ANTHROPIC_API_KEY` | [console.anthropic.com](https://console.anthropic.com/) — используется для извлечения заявок из текста на русском/кыргызском/английском. |

Ни один из этих сервисов не подключается автоматически — агент не может получить доступ к
WhatsApp Business, Telegram-группам или базе данных без того, чтобы вы явно выдали
соответствующие учётные данные и права (в т.ч. согласие администратора на подключение
конкретной Telegram-группы, см. `TelegramGroup`).

## Подключение Telegram-группы для пассивного чтения

Добавление группы в список разрешённых — ручное действие администратора (сейчас через прямую
запись в таблицу `TelegramGroup` или Prisma Studio: `npm run db:studio`). Агент не читает и не
обрабатывает сообщения ни в одной группе, где нет активной записи `isActive = true`.
